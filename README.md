# Розробка застосунків зі штучним інтелектом

П’ять практичних робіт в одному репозиторії. Код і інтерфейси українською; кожна робота запускається незалежно.

| Папка | Застосунок | Порт |
|---|---|---|
| pr1 | Погода Open-Meteo | 8001 |
| pr2 | Локальна детекція YOLO | 8002 |
| pr3 | Підтримка через LLM API | 8003 |
| pr4 | Діалог, JSON Schema, бюджет контексту | 8004 |
| pr5 | E5 та BM25 по базі знань | 8005 |

Почніть з README.md потрібної папки. Python 3.11/3.12; окреме віртуальне середовище для кожної роботи. Не запускайте кілька робіт з назвою пакета app в одному Python-процесі.

## Що потрібно налаштувати
- ПР1: доступ до Open-Meteo, ключ не потрібен.
- ПР2: перше завантаження ваг YOLO; оцінювання описано в pr2/eval.
- ПР3–ПР4: скопіюйте .env.example у .env, впишіть власний ключ і доступну назву моделі. Жодного ключа в архіві немає.
- ПР5: завантаження E5 та `python ingest.py` перед запуском. Індекс відтворюється, до Git не входить.

Статус фактичних перевірок і невиконаних зовнішніх експериментів: **VALIDATION.md**. Сценарії порівняння створюють справжні вимірювання; відсутні результати не замінено вигаданими.

## Перевірки коду
```bash
python -m pip install -r requirements-test.txt
python -m unittest discover -s tests -v
```

## Перший комміт
Розпакуйте архів і відкрийте термінал у папці ai-practicals:
```bash
git init -b main
git add .
git status
git commit -m "Додано практичні роботи 1–5"
git remote add origin https://github.com/YOUR_LOGIN/YOUR_REPOSITORY.git
git push -u origin main
```
На GitHub попередньо створіть порожній репозиторій. Архів не містить .git або вигаданої історії розробки. Подальші зміни коммітьте окремо.
